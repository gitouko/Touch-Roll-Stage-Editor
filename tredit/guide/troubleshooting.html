When something goes wrong

The editor won't save. It tells you why. Usually something is outside the area the game can handle, such as an object off the edge of the stage or a platform too far out to be drawn. Move it back, or widen the drawing range under Stage > Drawing range.

The 3D view is empty. It needs PyOpenGL and numpy. Click Install PyOpenGL and numpy… in the 3D view (or use Help > Packages…), then restart the editor. You can also let run_editor.bat install them, or run py -3 -m pip install --user PyOpenGL numpy yourself. The packaged program already has them.

Which packages do I have? Help > Packages… lists the Python packages the editor uses, with the version you have, and installs any that are missing.

I lost my edits. If backups are on (Edit > Settings… > Saving and testing), the editor writes a plan of your edits every few minutes. Click Open the backup folder there, then open your ROM and bring the newest one back with File > Import edits.

The ball falls through something I built. Check that it's marked Solid, and press C to see its collision. For imported models, see the page on importing: the faces may be pointing the wrong way.

Something I built isn't visible in the game. Check that it's marked Drawn, and that it's facing up (for models). Very large stages can also run out of drawing room; see Drawing range.

A stage freezes in the game. Undo your last few changes and try again, one at a time. Keep the number of triangles and the size of animations within what the editor recommends. If you find a change that reliably freezes the game, it's worth reporting with the saved .patch.json.

The editor itself crashes. A window shows what went wrong, and the details are saved in a file called error.log. Your ROM is never changed, and your last save is safe.
